** Overview

This phase adds an *optional, opt-in* way to interact with *external (non-Monero)
EVM chains* from the sovereign node, using *=cast=* (the Foundry CLI). It is the
first tier *beyond* the Monero-native core — hence the 30s file band, deliberately
outside the 10–20 install sequence — per the widened project scope: a *sovereign,
privacy-first crypto stack anchored by Monero*.

This is *general EVM-interop infrastructure*, not a use-case recipe. =cast= is a
CLI signer that talks JSON-RPC directly to an EVM node: it covers *receive* (just
an address), *balances*, *transfers*, and *direct contract calls*
(=cast call= for reads, =cast send= for writes). No dapp frontend, no browser, no
Cloudflare-fronted website in the loop — so it routes cleanly over Tor and is
fully auditable and scriptable. (A browser-based dapp fallback — the Rabby
extension in the existing Mullvad-Chromium path — is a *separate, later* component
and is not built here.)

It is *off by default*. Nothing is installed unless =cast_enabled: true= in
=config.yml=. Even when enabled there is *no systemd service and no autostart*:
=cast= is a CLI you invoke by hand, and its network path (a dedicated Tor inside a
throwaway network namespace) only exists for the duration of a single invocation.

*** Dependencies

This phase depends on *privacy* (Tor must be installed — phase =privacy=) and
the *sandbox* phase's hardening posture. It does *NOT* depend on monerod or
mining: EVM interop is independent of the Monero node.

*** Why Tor in a network namespace (and not torsocks or a proxy flag)

=cast= is a statically-linked Rust binary. Two tempting routes both fail:

- *=torsocks=* works by =LD_PRELOAD=-intercepting libc calls. A static Rust
  binary has libc compiled in (or issues raw syscalls), so the interposition is
  a no-op and traffic egresses *in the clear* — and torsocks then *runs anyway*
  (fail-*open*). Unacceptable.
- *A SOCKS proxy env var* (=ALL_PROXY=socks5h://…=) relies on Foundry's reqwest
  stack having the =socks= feature compiled in. Its release builds *do not*, so
  =cast= rejects a SOCKS URL. Not dependable.

So we put =cast= in a *network namespace whose only egress is Tor*. A dedicated
=tor= runs inside the namespace; nftables transparently redirects =cast='s TCP to
Tor's =TransPort= and its DNS to Tor's =DNSPort=, with a default-=drop= policy.
Anything that tries to leave another way — raw syscalls, ignored proxy env, a
static binary — has *nowhere to go* and is dropped. This is *fail-closed* and
*binary-agnostic*, and every rule is plain =ip=/=nft= you can read. The launcher
additionally *refuses to run =cast= until it has confirmed* (via
=check.torproject.org/api/ip=) that the namespace's exit really is a Tor relay.

*** Why cosign / Sigstore (and not a pinned GPG key)

Every other download-verifying phase here pins a maintainer *GPG key* in =keys/=
and checks a signed hashes manifest. *Foundry publishes no GPG key.* Its
first-party signature chain is *Sigstore / cosign*: each versioned release ships
=foundry_<ver>_linux_amd64.sigstore.json=, a keyless signature produced by the
release GitHub Actions workflow and verifiable *offline* against a *pinned
certificate identity* (the workflow path + the exact tag). We therefore verify
the SHA-256, then =cosign verify-blob= against that pinned identity, failing
closed on any mismatch. The pinned identity is recorded in =keys/README.md=
alongside the GPG fingerprints — it is the same kind of trust anchor, just a
different signature scheme. (We pin a *versioned* tag, never the rolling =stable=
tag: only versioned tags carry the =.sha256= + =.sigstore.json=.)

*** Custody: hardware wallet first, no resident hot key

=cast= signs with a *hardware wallet* (=cast … --trezor= / =--ledger=): the
private key never touches the disk, and every signature needs a physical button
press at the box's console. We install the Trezor udev rules so this works for
the =dev= user. An *encrypted keystore* (=cast wallet import --keystore=, stored
under =~/.foundry/keystores=) is the *no-hardware fallback* — still never a
plaintext key on disk. There is no default key material; you provision one
out-of-band.

*** Remote-operator signing: the propose/approve split

When the box is driven by *laptop-side Claude over wg0* (the =ops= sandboxed
front door — see =org/14-sandbox.org=), the agent must never hold the signing
material or sit in the authorization decision. Signing is therefore split:

- =cast-propose= runs as the sandboxed =ops= uid and is *fully offline*. It
  ABI-encodes the calldata locally (=cast calldata=, pure local serialization),
  and writes a staged artifact — =to=, =value=, =calldata=, =chain=, signature +
  args — into a shared spool. *No key, no nonce/gas lookup, no broadcast*: the
  sandboxed session never touches the network or the keys. (Live simulation is
  deliberately deferred to approval, so the untrusted party emits no packets at
  all — nothing to leak to an RPC.)
- =cast-approve= is run by *you*, the operator, as the *key-owner uid* (never
  =ops=). It re-reads the artifact, *independently re-encodes* the calldata from
  the human-readable signature+args and refuses to proceed unless that matches
  the staged calldata (so what you read is provably what you sign), *re-simulates
  over the Tor netns* via =cast-tor=, shows you everything, and only after you
  type =APPROVE= signs+broadcasts.

The decisive property: the dangerous part of a dapp trade is the *calldata* —
opaque hex you cannot eyeball. The authorization decision must not rest on the
untrusted agent's own rendering of it, so the *trusted* =cast-approve= re-derives
and re-simulates what it is about to sign. =ops= stays out of the trust path for
the decision, not merely away from the key.

*Custody is selectable per trade* with =cast-approve --custody=:
- =keystore= — the encrypted keystore on the box; you type its password on *your*
  approve TTY (it never reaches =ops=). Fully remote.
- =trezor= — a Trezor at the box console; you confirm with the physical button.
  USB already passes through the netns, so this is one flag from =keystore=.
- =airgap= — a *reserved future seam* (Trezor at the laptop: box emits an unsigned
  tx and broadcasts, laptop signs offline). Documented, not yet built.

No new sudo grant is added for this: =cast-approve= runs *as* the key owner and
delegates only the netns broadcast to the existing =sudo cast-tor= grant, so
=ops= gains *nothing* privileged. The propose spool is transient scratch and is
not backed up.

** Verify and Install the cast Binary

Foundry's versioned release ships =foundry_<ver>_linux_amd64.tar.gz= (bundling
=forge=, =cast=, =anvil=, =chisel=), a =.sha256= of that archive, and a
=.sigstore.json= cosign bundle. We check the SHA-256, then =cosign verify-blob=
the archive against the *pinned* certificate identity for this exact tag, and
only then extract =cast= into a versioned =/opt= directory. A re-run never trusts
a partially-downloaded or tampered file.

#+begin_src yaml :tangle ../ansible/fragments/30-interop.yml
    - name: Set versioned Foundry directory
      set_fact:
        foundry_versioned_dir: "{{ foundry_install_dir }}-{{ foundry_version }}"
      when: cast_enabled | bool
      tags: [interop]

    - name: Check if this cast version is already installed
      stat:
        path: "{{ foundry_versioned_dir }}/cast"
      register: cast_version_exists
      when: cast_enabled | bool
      tags: [interop]

    - name: Download Foundry release archive
      get_url:
        url: "{{ foundry_release_base }}/{{ foundry_tarball }}"
        dest: /tmp/foundry.tar.gz
        mode: '0644'
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Download Foundry SHA-256 file
      get_url:
        url: "{{ foundry_release_base }}/{{ foundry_sha_file }}"
        dest: /tmp/foundry.sha256
        mode: '0644'
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Download Foundry Sigstore bundle
      get_url:
        url: "{{ foundry_release_base }}/{{ foundry_sigstore_file }}"
        dest: /tmp/foundry.sigstore.json
        mode: '0644'
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Extract expected SHA-256 for the Foundry archive
      shell: |
        awk '{ print $1; exit }' /tmp/foundry.sha256
      register: foundry_expected_hash
      changed_when: false
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Fail if expected Foundry hash is not a sha256 hex string
      fail:
        msg: |
          Could not extract a valid sha256 from {{ foundry_sha_file }}
          (got: '{{ foundry_expected_hash.stdout }}').

          The release asset naming may have changed, or {{ foundry_version }}
          may be the rolling `stable` tag (which omits the .sha256). Pin a
          versioned tag and check the assets at
          https://github.com/foundry-rs/foundry/releases/tag/{{ foundry_version }}
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
        - foundry_expected_hash.stdout is not match('^[a-f0-9]{64}$')
      tags: [interop]

    - name: Compute Foundry download hash
      stat:
        path: /tmp/foundry.tar.gz
        checksum_algorithm: sha256
      register: foundry_download_stat
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Fail if Foundry archive hash mismatch
      fail:
        msg: |
          Foundry archive SHA-256 verification failed!
          Expected: {{ foundry_expected_hash.stdout }}
          Got:      {{ foundry_download_stat.stat.checksum }}
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
        - foundry_download_stat.stat.checksum != foundry_expected_hash.stdout
      tags: [interop]

    # The cosign bundle is the real first-party signature: a keyless Sigstore
    # signature whose certificate identity is the Foundry release workflow at
    # THIS exact tag. Pinning --certificate-identity to that SAN (not a loose
    # regexp) means a binary signed by any other workflow/tag/repo fails closed.
    # The signature is over the .tar.gz, so we verify the archive, then extract.
    - name: Verify Foundry archive Sigstore signature (cosign)
      command: >
        cosign verify-blob
        --bundle /tmp/foundry.sigstore.json
        --certificate-identity {{ foundry_cosign_identity }}
        --certificate-oidc-issuer {{ foundry_cosign_issuer }}
        /tmp/foundry.tar.gz
      changed_when: false
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Create versioned Foundry directory
      file:
        path: "{{ foundry_versioned_dir }}"
        state: directory
        owner: "{{ dev_user }}"
        group: "{{ dev_user }}"
        mode: '0755'
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    # Extract only `cast` from the verified archive. forge/anvil/chisel are dev
    # tooling we deliberately do not install on the node.
    - name: Extract verified cast binary
      unarchive:
        src: /tmp/foundry.tar.gz
        dest: "{{ foundry_versioned_dir }}"
        remote_src: yes
        include:
          - cast
        owner: "{{ dev_user }}"
        group: "{{ dev_user }}"
      register: cast_installed
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Ensure cast is executable
      file:
        path: "{{ foundry_versioned_dir }}/cast"
        mode: '0755'
      when:
        - cast_enabled | bool
        - not cast_version_exists.stat.exists
      tags: [interop]

    - name: Clean up Foundry download files
      file:
        path: "{{ item }}"
        state: absent
      loop:
        - /tmp/foundry.tar.gz
        - /tmp/foundry.sha256
        - /tmp/foundry.sigstore.json
      when:
        - cast_enabled | bool
        - cast_installed.changed
      tags: [interop]

    - name: Update Foundry symlink to current version
      file:
        src: "{{ foundry_versioned_dir }}"
        dest: "{{ foundry_install_dir }}"
        state: link
        force: yes
      when: cast_enabled | bool
      tags: [interop]
#+end_src

** Dedicated Tor Config for the Interop Namespace

A *separate* Tor instance, run *only inside* the =interop= network namespace by
the launcher below. It listens on the namespace's loopback; the namespace's
nftables rules redirect =cast='s traffic to these ports. It is unrelated to the
system Tor from the =privacy= phase (which keeps its own =torrc=, ports, and data
dir untouched).

#+begin_src conf :tangle ../configs/templates/interop-torrc.j2
## Dedicated Tor for the interop network namespace.
## Generated from org/30-interop.org. Started on demand by cast-tor, never as a
## service. DataDirectory is passed on the command line (interop_tor_data_dir).

# No SOCKS — cast cannot use it; we torify transparently instead.
SocksPort 0

# Transparent proxy + DNS for everything in the namespace. Stream isolation so
# distinct destinations get distinct circuits.
#
# Bind on the namespace's veth IP, NOT 127.0.0.1: cast's traffic to a remote RPC
# gets the veth IP as its source, and REDIRECT-ing that to a loopback-bound port
# makes the kernel drop the packet as a martian (non-loopback source -> 127/8).
# dnat-ing to this veth IP (see cast-tor) keeps source and dest on the same real
# local IP, which routes normally.
TransPort {{ interop_veth_ns_ip }}:{{ interop_tor_trans_port }} IsolateClientAddr IsolateDestAddr IsolateDestPort
DNSPort {{ interop_veth_ns_ip }}:{{ interop_tor_dns_port }}

# Map resolved names (incl. .onion) to virtual IPs the TransPort recognizes, so
# an .onion RPC endpoint works the same as a clearnet one.
AutomapHostsOnResolve 1
VirtualAddrNetworkIPv4 10.192.0.0/10

ClientOnly 1
AvoidDiskWrites 1
Log notice stderr
#+end_src

        group: root

      when: cast_enabled | bool
      tags: [interop]

    - name: Create interop Tor data directory
      file:
        path: "{{ interop_tor_data_dir }}"
        state: directory
        owner: tor

        mode: '0700'
      when: cast_enabled | bool
      tags: [interop]

    # Inside `ip netns exec`, /etc/netns/<ns>/* is bind-mounted over /etc/*.
    # Point the namespace's resolver at its own loopback so getaddrinfo() hits
    # the redirect rule (-> Tor DNSPort), never a real resolver.
    - name: Create interop netns /etc directory
      file:
        path: "/etc/netns/{{ interop_netns }}"
        state: directory
        owner: root
        group: root
        mode: '0755'
      when: cast_enabled | bool
      tags: [interop]

    - name: Deploy interop netns resolv.conf (loopback only)
      copy:
        content: "nameserver 127.0.0.1\n"
        dest: "/etc/netns/{{ interop_netns }}/resolv.conf"
        owner: root
        group: root
        mode: '0644'
      when: cast_enabled | bool
      tags: [interop]

    # systemd-networkd ships 80-container-ve.network matching `ve-*` (for nspawn
    # container veths); it would grab cast-tor's ve-interop-* host side, assign
    # it a 192.168.x/link-local address, and clobber the 10.x gateway the
    # namespace needs — so the namespace's Tor gets "No route to host". This
    # higher-priority rule (10- sorts before 80-) marks ve-interop-* Unmanaged,
    # so networkd leaves cast-tor's addressing alone.
    - name: Keep systemd-networkd off the cast-tor veth
      copy:
        content: |
          # Generated from org/30-interop.org. Leave the cast-tor veth alone:
          # ve-interop-* otherwise matches networkd's built-in
          # 80-container-ve.network, which overwrites cast-tor's address and
          # breaks the namespace's egress.
          [Match]
          Name=ve-interop-*

          [Link]
          Unmanaged=yes
        dest: /etc/systemd/network/10-interop-veth.network
        owner: root
        group: root
        mode: '0644'
      register: interop_veth_netdev
      when: cast_enabled | bool
      tags: [interop]

    - name: Reload systemd-networkd so the veth rule takes effect
      command: networkctl reload
      when:
        - cast_enabled | bool
        - interop_veth_netdev.changed
      tags: [interop]
#+end_src

** Fail-Closed Tor Launcher (=cast-tor=)

This wrapper is to =cast= what =mullvad-browser.py= is to the browser: it brings
the private network path up, *verifies it before use*, runs the tool, and tears
everything down on exit. Run it as =cast-tor <cast args>= — it re-execs under
=sudo= for the privileged namespace setup, then runs =cast= as you.

What it guarantees:
- A throwaway =interop= network namespace whose *only* viable egress is Tor.
- nftables with =policy drop=: =cast='s TCP is redirected to Tor's =TransPort=,
  its DNS to Tor's =DNSPort=, and *everything else is dropped* — no leak path.
- It *refuses to run =cast=* unless =check.torproject.org/api/ip= confirms the
  exit is a Tor relay.
- A =trap= tears the namespace, the dedicated Tor, and the host masquerade rule
  down however the script exits (success, error, Ctrl-C).

#+begin_src bash :tangle ../configs/templates/cast-tor.j2
#!/bin/bash
# Fail-closed Tor launcher for cast (Foundry).
# Generated from org/30-interop.org.
#
# Runs `cast` inside a throwaway network namespace whose only egress is a
# dedicated Tor. nftables redirects cast's TCP -> Tor TransPort and DNS ->
# Tor DNSPort with a default-drop policy, so nothing can leak around Tor.
# The launcher confirms a Tor exit before running cast, and tears the whole
# setup down on exit.

set -euo pipefail

NETNS="{{ interop_netns }}"
VETH_HOST="ve-interop-h"
VETH_NS="ve-interop-n"
HOST_IP="{{ interop_veth_host_ip }}"
NS_IP="{{ interop_veth_ns_ip }}"
SUBNET="{{ interop_veth_subnet }}"
TOR_RC="/etc/tor/interop-torrc"
TOR_DATA="{{ interop_tor_data_dir }}"
TRANS_PORT="{{ interop_tor_trans_port }}"
DNS_PORT="{{ interop_tor_dns_port }}"
CAST="{{ foundry_install_dir }}/cast"

# The user cast should run as (the human who invoked us, even via sudo).
RUN_USER="${SUDO_USER:-{{ dev_user }}}"

if [ ! -x "$CAST" ]; then
  echo "cast-tor: cast not found/verified at $CAST" >&2
  echo "Enable and install the interop phase first:" >&2
  echo "  set cast_enabled: true in config.yml, then" >&2
  echo "  ansible-playbook playbook.yml --tags interop -K" >&2
  exit 1
fi

# Privileged setup needs root; re-exec under sudo, preserving args.
if [ "$(id -u)" -ne 0 ]; then
  exec sudo -- "$0" "$@"
fi

WAN_IF="$(ip route show default 2>/dev/null | awk '/default/ {print $5; exit}')"
if [ -z "$WAN_IF" ]; then
  echo "cast-tor: no default route — cannot reach Tor network" >&2
  exit 1
fi

TOR_PID=""
cleanup() {
  set +e
  [ -n "$TOR_PID" ] && kill "$TOR_PID" 2>/dev/null
  # Kill any stragglers still living in the namespace.
  ip netns pids "$NETNS" 2>/dev/null | xargs -r kill 2>/dev/null
  # Remove the host masquerade + forward-allow rules we added.
  iptables -t nat -D POSTROUTING -s "$SUBNET" -o "$WAN_IF" -j MASQUERADE 2>/dev/null
  iptables -D FORWARD -i "$VETH_HOST" -o "$WAN_IF" -j ACCEPT 2>/dev/null
  iptables -D FORWARD -i "$WAN_IF" -o "$VETH_HOST" -j ACCEPT 2>/dev/null
  ip netns del "$NETNS" 2>/dev/null
  ip link del "$VETH_HOST" 2>/dev/null
}
trap cleanup EXIT INT TERM

# Clear any stale namespace from a previous crashed run.
ip netns del "$NETNS" 2>/dev/null || true
ip link del "$VETH_HOST" 2>/dev/null || true

# 1. Namespace + veth pair. The namespace's default route is the host side of
#    the veth; it has no other interface.
ip netns add "$NETNS"
ip link add "$VETH_HOST" type veth peer name "$VETH_NS"
ip link set "$VETH_NS" netns "$NETNS"
# Belt-and-braces: drop any address a network manager raced to assign before we
# set ours. The deployed 10-interop-veth.network tells systemd-networkd to leave
# ve-interop-* unmanaged (its built-in 80-container-ve.network matches ve-* and
# would otherwise overwrite this address and kill the namespace's egress).
ip addr flush dev "$VETH_HOST" 2>/dev/null || true
ip addr add "$HOST_IP/24" dev "$VETH_HOST"
ip link set "$VETH_HOST" up
ip -n "$NETNS" addr add "$NS_IP/24" dev "$VETH_NS"
ip -n "$NETNS" link set "$VETH_NS" up
ip -n "$NETNS" link set lo up
ip -n "$NETNS" route add default via "$HOST_IP"

# 2. Host masquerade + forwarding for ONLY this namespace's subnet out the WAN.
#    The only namespace traffic that ever reaches here is the dedicated Tor's
#    own outbound (everything else is redirected to Tor or dropped, in step 4).
#    The FORWARD rules are inserted at the TOP of the chain so they take effect
#    even though ufw's default forward policy is DROP (this box runs ufw).
sysctl -q -w net.ipv4.ip_forward=1
iptables -t nat -A POSTROUTING -s "$SUBNET" -o "$WAN_IF" -j MASQUERADE
iptables -I FORWARD -i "$VETH_HOST" -o "$WAN_IF" -j ACCEPT
iptables -I FORWARD -i "$WAN_IF" -o "$VETH_HOST" -j ACCEPT

# 3. Dedicated Tor INSIDE the namespace, running as the tor user so the
#    owner-match in step 4 can exempt its outbound. Persistent DataDirectory
#    means guard nodes are remembered, so later runs bootstrap fast.
ip netns exec "$NETNS" runuser -u tor -- \
  tor -f "$TOR_RC" --DataDirectory "$TOR_DATA" --quiet &
TOR_PID=$!

# 4. nftables INSIDE the namespace — the fail-closed core.
#    nat_out: tor's own traffic (and anything already aimed at the veth IP) passes
#    through; DNS is dnat'd to Tor's DNSPort and every other TCP to Tor's
#    TransPort — both on the veth IP ($NS_IP), NOT 127.0.0.1. cast's traffic has
#    the veth IP as its source, and the kernel drops a non-loopback-source packet
#    redirected to 127/8 as a martian; dnat-ing to the veth IP keeps source and
#    dest on the same real local IP, which routes normally.
#    filter_out: default DROP — only loopback, traffic to the veth IP (the dnat
#    target), and tor's own egress may leave. A static binary issuing raw
#    syscalls has nowhere to go.
ip netns exec "$NETNS" nft -f - <<EOF
table ip torify {
  chain nat_out {
    type nat hook output priority -100;
    meta skuid tor return
    ip daddr $NS_IP return
    meta l4proto udp udp dport 53 dnat to $NS_IP:$DNS_PORT
    meta l4proto tcp tcp dport 53 dnat to $NS_IP:$DNS_PORT
    meta l4proto tcp dnat to $NS_IP:$TRANS_PORT
  }
  chain filter_out {
    type filter hook output priority 0; policy drop;
    oifname "lo" accept
    ip daddr $NS_IP accept
    meta skuid tor accept
    ct state established,related accept
  }
}
EOF

# 5. Fail-closed verification: do not run cast until the namespace's exit is a
#    confirmed Tor relay. This also waits out Tor's bootstrap (the check only
#    succeeds once circuits are up).
confirm_tor() {
  local out
  for _ in $(seq 1 30); do
    out="$(ip netns exec "$NETNS" curl -s --max-time 15 \
            https://check.torproject.org/api/ip 2>/dev/null || true)"
    if printf '%s' "$out" | grep -q '"IsTor":true'; then
      echo "cast-tor: Tor exit confirmed ($(printf '%s' "$out" \
            | grep -o '"IP":"[^"]*"'))" >&2
      return 0
    fi
    sleep 2
  done
  return 1
}

if ! confirm_tor; then
  echo "cast-tor: REFUSING to run — could not confirm a Tor exit." >&2
  echo "  No traffic was sent in the clear; the namespace is fail-closed." >&2
  exit 1
fi

# 6. Run cast as the invoking user, inside the torified namespace. We do NOT
#    exec, so the trap above still tears everything down afterwards.
set +e
ip netns exec "$NETNS" runuser -u "$RUN_USER" -- \
  env HOME="/home/$RUN_USER" "$CAST" "$@"
rc=$?
set -e
exit "$rc"

*** cast-propose — offline transaction staging (runs as =ops=)

Pure-local ABI encoding with =cast calldata=; *no network, no key, no
broadcast*. Writes a strict =KEY=VALUE= artifact that =cast-approve= re-validates
field by field. A plain value transfer carries no calldata (=SIG= empty); a
contract call requires =--sig 'f(types)'= so the calldata is human-decodable and
re-derivable at approval.

#+begin_src bash :tangle ../configs/templates/cast-propose.j2
#!/bin/bash
# cast-propose — stage an EVM transaction for operator approval (OFFLINE).
# Generated from org/30-interop.org.
#
# Runs as the sandboxed `ops` uid inside the ForceCommand jail. It makes NO
# network connection: it only ABI-encodes the calldata locally with `cast
# calldata` and writes a staged artifact to the shared proposal spool. The
# operator later runs `cast-approve`, which re-encodes, re-simulates over Tor,
# and signs+broadcasts. No key, no nonce/gas lookup, no broadcast happen here —
# so the sandboxed session never touches the network or the signing material.
set -euo pipefail

CAST="{{ foundry_install_dir }}/cast"
SPOOL="{{ interop_proposal_dir }}"
CUSTODY_DEFAULT="{{ interop_custody_default }}"

usage() {
  cat >&2 <<'USAGE'
Usage: cast-propose --to <0xADDR> --chain <ID> [options] [ARG...]
  --to 0xADDR        destination contract / account (required)
  --chain ID         EVM chain id, e.g. 1 (required)
  --value WEI        native value to send, decimal wei (default 0)
  --sig 'f(t,...)'   function signature; ARGs after it are ABI-encoded offline
  --custody NAME     suggested custody: keystore | trezor | airgap
  --note 'text'      free-text reminder shown at approval (single line)
  ARG...             function arguments (only meaningful with --sig)

Stages a transaction WITHOUT signing or broadcasting, then print its path.
Approve it (as the key owner, NOT ops):  cast-approve <proposal-file>
USAGE
  exit 2
}

TO="" CHAIN="" VALUE="0" SIG="" NOTE="" CUSTODY="$CUSTODY_DEFAULT"
ARGS=()
while [ $# -gt 0 ]; do
  case "$1" in
    --to)      TO="${2:?}"; shift 2 ;;
    --chain)   CHAIN="${2:?}"; shift 2 ;;
    --value)   VALUE="${2:?}"; shift 2 ;;
    --sig)     SIG="${2:?}"; shift 2 ;;
    --custody) CUSTODY="${2:?}"; shift 2 ;;
    --note)    NOTE="${2:?}"; shift 2 ;;
    --)        shift; ARGS+=("$@"); break ;;
    -h|--help) usage ;;
    -*)        echo "cast-propose: unknown option: $1" >&2; usage ;;
    *)         ARGS+=("$1"); shift ;;
  esac
done

# --- validate (fail closed; these constrain what the operator will sign) ------
[ -n "$TO" ] && [ -n "$CHAIN" ] || usage
[[ "$TO"      =~ ^0x[0-9a-fA-F]{40}$ ]]       || { echo "cast-propose: --to must be a 0x 20-byte address" >&2; exit 2; }
[[ "$CHAIN"   =~ ^[0-9]+$ ]]                   || { echo "cast-propose: --chain must be a decimal chain id" >&2; exit 2; }
[[ "$VALUE"   =~ ^[0-9]+$ ]]                   || { echo "cast-propose: --value must be decimal wei" >&2; exit 2; }
[[ "$CUSTODY" =~ ^(keystore|trezor|airgap)$ ]] || { echo "cast-propose: --custody must be keystore|trezor|airgap" >&2; exit 2; }
# Signature charset: name(types). The arg-list class lists ] first (literal) so
# array types like uint256[] validate; the regex lives in a var so bash does not
# mis-parse the brackets as a [[ ]] terminator.
sig_re='^[A-Za-z_][A-Za-z0-9_]*\([]A-Za-z0-9_,[ ]*\)$'
if [ -n "$SIG" ] && ! [[ "$SIG" =~ $sig_re ]]; then
  echo "cast-propose: --sig must look like 'name(type,...)'" >&2; exit 2
fi
[ ${#ARGS[@]} -eq 0 ] || [ -n "$SIG" ] \
  || { echo "cast-propose: function ARGs given without --sig" >&2; exit 2; }
NOTE="${NOTE//$'\n'/ }"   # the artifact is line-based; keep NOTE single-line

if [ ! -x "$CAST" ]; then
  echo "cast-propose: cast not found at $CAST (enable the interop phase)" >&2
  exit 1
fi
if [ ! -d "$SPOOL" ] || [ ! -w "$SPOOL" ]; then
  echo "cast-propose: proposal spool $SPOOL is missing or not writable" >&2
  echo "  (deploy the interop phase; the ops jail bind-mounts it)" >&2
  exit 1
fi

# --- encode calldata OFFLINE (no network) -------------------------------------
# `cast calldata` is pure local ABI encoding. A plain value transfer has none.
CALLDATA="0x"
if [ -n "$SIG" ]; then
  CALLDATA="$("$CAST" calldata "$SIG" "${ARGS[@]}")"
  [[ "$CALLDATA" =~ ^0x[0-9a-fA-F]*$ ]] \
    || { echo "cast-propose: cast calldata produced unexpected output" >&2; exit 1; }
fi

# --- write the staged artifact (strict KEY=VALUE; approve re-validates) --------
umask 0027
ts="$(date -u +%Y%m%dT%H%M%SZ)"
out="$SPOOL/proposal-${ts}-$$.casttx"
{
  echo "# cast-propose staged transaction. UNTRUSTED input: cast-approve"
  echo "# re-encodes, re-simulates and re-displays everything below before signing."
  echo "CAST_PROPOSAL_VERSION=1"
  echo "CHAIN_ID=$CHAIN"
  echo "TO=$TO"
  echo "VALUE=$VALUE"
  echo "SIG=$SIG"
  echo "ARGC=${#ARGS[@]}"
  i=0; for a in "${ARGS[@]}"; do echo "ARG_${i}=$a"; i=$((i+1)); done
  echo "CALLDATA=$CALLDATA"
  echo "CUSTODY=$CUSTODY"
  echo "NOTE=$NOTE"
} > "$out"

# --- human-readable summary (informational; approve recomputes the truth) ------
{
  echo "cast-propose: staged $out"
  echo "  chain    : $CHAIN"
  echo "  to       : $TO"
  echo "  value    : $VALUE wei"
  echo "  function : ${SIG:-<plain value transfer>}"
  i=0; for a in "${ARGS[@]}"; do echo "  arg[$i]   : $a"; i=$((i+1)); done
  echo "  calldata : $CALLDATA"
  echo "  custody  : $CUSTODY (suggested)"
  echo "  note     : ${NOTE:-<none>}"
  echo ""
  echo "Approve it (as the key owner, NOT ops):  cast-approve $out"
} >&2
echo "$out"
#+end_src

*** cast-approve — trusted review, simulate, sign (runs as the key owner)

Run by *you*, as the key-owner uid (never =ops=; the script refuses root/ops).
It re-derives the calldata from the artifact's signature+args and aborts on any
mismatch, re-simulates over the Tor netns via =sudo cast-tor= (the existing
grant — no new privilege), prints everything, and signs only after you type
=APPROVE=. The keystore password / Trezor button is supplied here, never via
=ops=.

#+begin_src bash :tangle ../configs/templates/cast-approve.j2
#!/bin/bash
# cast-approve — review, simulate over Tor, then sign+broadcast a staged tx.
# Generated from org/30-interop.org.
#
# Run by the OPERATOR, as the key-owner uid — NOT by `ops`, NOT under sudo. It
# re-derives the transaction from the (untrusted) staged artifact, re-simulates
# it over the fail-closed Tor netns via `sudo cast-tor`, shows it, and — only
# after you type APPROVE — signs+broadcasts. The signing material (keystore
# password / Trezor button) is supplied here, on the operator's TTY, and never
# reaches an ops/Claude session.
set -euo pipefail

CAST="{{ foundry_install_dir }}/cast"
CAST_TOR="/usr/local/bin/cast-tor"
SPOOL="{{ interop_proposal_dir }}"
OPS_USER="{{ ops_user }}"
RPC_DEFAULT="{{ cast_rpc_url }}"
VALUE_CAP="{{ interop_value_cap }}"
declare -a TO_ALLOWLIST=( {% for a in interop_to_allowlist %}"{{ a }}" {% endfor %})

usage() {
  cat >&2 <<'USAGE'
Usage: cast-approve <proposal-file> [options]
  --custody NAME     keystore | trezor | airgap  (default: artifact's suggestion)
  --account NAME     keystore account name (keystore custody)
  --keystore PATH    keystore file path (keystore custody, alt to --account)
  --rpc-url URL      JSON-RPC endpoint (default: cast_rpc_url)
  --from 0xADDR      sender address used for the read-only simulation (optional)

Re-derives + re-simulates the staged tx over Tor and, after you type APPROVE,
signs+broadcasts it. Run as the key owner, NOT as ops and NOT under sudo.
USAGE
  exit 2
}

# Must run as the key owner: not root/sudo (keystore lives in the owner's HOME),
# and never as the sandboxed ops uid (defense-in-depth; ops also lacks the
# cast-tor sudo grant, so a broadcast would fail closed anyway).
if [ "$(id -u)" -eq 0 ]; then
  echo "cast-approve: run as the key owner, not as root/sudo." >&2; exit 3
fi
if [ "$(id -un)" = "$OPS_USER" ]; then
  echo "cast-approve: must NOT be run as $OPS_USER — run as the key owner." >&2; exit 3
fi

PROPOSAL="" CUSTODY="" ACCOUNT="" KEYSTORE="" RPC="" FROM=""
while [ $# -gt 0 ]; do
  case "$1" in
    --custody)  CUSTODY="${2:?}"; shift 2 ;;
    --account)  ACCOUNT="${2:?}"; shift 2 ;;
    --keystore) KEYSTORE="${2:?}"; shift 2 ;;
    --rpc-url)  RPC="${2:?}"; shift 2 ;;
    --from)     FROM="${2:?}"; shift 2 ;;
    -h|--help)  usage ;;
    -*)         echo "cast-approve: unknown option: $1" >&2; usage ;;
    *)          PROPOSAL="$1"; shift ;;
  esac
done
[ -n "$PROPOSAL" ] || usage
RPC="${RPC:-$RPC_DEFAULT}"

# Resolve the proposal inside the spool; reject anything that escapes it.
case "$PROPOSAL" in
  /*) full="$PROPOSAL" ;;
  *)  full="$SPOOL/$PROPOSAL" ;;
esac
full="$(realpath -e -- "$full" 2>/dev/null || true)"
spool_real="$(realpath -e -- "$SPOOL")"
[ -n "$full" ] || { echo "cast-approve: no such proposal: $PROPOSAL" >&2; exit 2; }
case "$full" in
  "$spool_real"/*) : ;;
  *) echo "cast-approve: $full is outside the proposal spool $spool_real" >&2; exit 2 ;;
esac

# Read one KEY=VALUE line and validate it (fail closed on anything unexpected).
field() {
  local key="$1" re="$2" val
  val="$(grep -m1 "^${key}=" -- "$full" | cut -d= -f2- || true)"
  if ! [[ "$val" =~ $re ]]; then
    echo "cast-approve: field $key failed validation ('$val')" >&2; return 2
  fi
  printf '%s' "$val"
}

# field() runs in a command substitution (a subshell), so its failure must be
# caught with `|| exit` here — `set -e` does NOT abort the parent on a failed
# assignment, which would otherwise let a malformed field slip through.
VERSION="$(field CAST_PROPOSAL_VERSION '^1$')"                                  || exit 2
CHAIN="$(field CHAIN_ID '^[0-9]+$')"                                            || exit 2
TO="$(field TO '^0x[0-9a-fA-F]{40}$')"                                          || exit 2
VALUE="$(field VALUE '^[0-9]+$')"                                               || exit 2
SIG="$(field SIG '^([A-Za-z_][A-Za-z0-9_]*\([]A-Za-z0-9_,[ ]*\))?$')"          || exit 2
CALLDATA="$(field CALLDATA '^0x[0-9a-fA-F]*$')"                                 || exit 2
ARGC="$(field ARGC '^[0-9]+$')"                                                || exit 2
CUST_SUGGEST="$(field CUSTODY '^(keystore|trezor|airgap)$')"                    || exit 2
CUSTODY="${CUSTODY:-$CUST_SUGGEST}"
NOTE="$(grep -m1 '^NOTE=' -- "$full" | cut -d= -f2- || true)"
NOTE="$(printf '%s' "$NOTE" | tr -cd '[:print:]')"   # strip control/escape chars

declare -a ARGS=()
i=0
while [ "$i" -lt "$ARGC" ]; do
  v="$(grep -m1 "^ARG_${i}=" -- "$full" | cut -d= -f2-)" \
    || { echo "cast-approve: missing ARG_$i" >&2; exit 2; }
  ARGS+=("$v"); i=$((i+1))
done

# The trust pivot: independently RE-ENCODE the calldata from the human-readable
# signature+args and require it to equal the staged calldata. So what the
# operator reads (sig + args) is provably what gets signed — a compromised ops
# cannot stage a friendly-looking sig with hostile calldata.
expected="0x"
[ -n "$SIG" ] && expected="$("$CAST" calldata "$SIG" "${ARGS[@]}")"
if [ "${expected,,}" != "${CALLDATA,,}" ]; then
  echo "cast-approve: INTEGRITY FAILURE — calldata does not match sig+args." >&2
  echo "  staged    : $CALLDATA" >&2
  echo "  re-derived : $expected" >&2
  exit 4
fi

# Trusted-side guardrails (optional; empty config = no limit).
dec_gt() {  # echo 1 if non-negative decimal $1 > $2 (exact, no 64-bit overflow)
  local a="${1#"${1%%[!0]*}"}" b="${2#"${2%%[!0]*}"}"
  a="${a:-0}"; b="${b:-0}"
  if [ "${#a}" -ne "${#b}" ]; then [ "${#a}" -gt "${#b}" ] && echo 1 || echo 0; return; fi
  [[ "$a" > "$b" ]] && echo 1 || echo 0
}
if [ "${#TO_ALLOWLIST[@]}" -gt 0 ]; then
  ok=0; for a in "${TO_ALLOWLIST[@]}"; do [ "${a,,}" = "${TO,,}" ] && ok=1; done
  [ "$ok" = 1 ] || { echo "cast-approve: $TO not in interop_to_allowlist" >&2; exit 5; }
fi
if [ -n "$VALUE_CAP" ] && [ "$(dec_gt "$VALUE" "$VALUE_CAP")" = 1 ]; then
  echo "cast-approve: value $VALUE exceeds interop_value_cap $VALUE_CAP" >&2; exit 5
fi

cat <<REVIEW
=== cast-approve — review before signing ===
proposal : $full
chain id : $CHAIN
to       : $TO
value    : $VALUE wei
function : ${SIG:-<plain value transfer>}
$(i=0; for a in "${ARGS[@]}"; do echo "arg[$i]    : $a"; i=$((i+1)); done)
calldata : $CALLDATA   (verified: re-encodes from sig+args)
custody  : $CUSTODY
note     : ${NOTE:-<none>}
rpc      : ${RPC:-<none>}
REVIEW

# Re-simulate over Tor (read-only) via the existing fail-closed launcher. A
# revert here is shown LOUDLY but is NOT fatal: it may be a genuine failing tx,
# or just a msg.sender-dependent call simulated without --from. You are the
# trusted decision-maker — judge it at the APPROVE prompt below. (Pass --from
# <your-address> for a faithful msg.sender simulation.)
if [ -n "$RPC" ]; then
  echo "--- simulating over Tor (cast-tor call) ---"
  sudo "$CAST_TOR" call "$TO" ${SIG:+"$SIG"} "${ARGS[@]}" \
       ${VALUE:+--value "$VALUE"} ${FROM:+--from "$FROM"} \
       --chain "$CHAIN" --rpc-url "$RPC" \
    || echo "cast-approve: !! simulation reverted/failed — review carefully before approving."
  echo "--- gas estimate over Tor ---"
  sudo "$CAST_TOR" estimate "$TO" ${SIG:+"$SIG"} "${ARGS[@]}" \
       ${VALUE:+--value "$VALUE"} ${FROM:+--from "$FROM"} \
       --chain "$CHAIN" --rpc-url "$RPC" \
    || echo "cast-approve: gas estimate failed (continuing)."
else
  echo "cast-approve: no --rpc-url / cast_rpc_url set — skipping Tor simulation." >&2
fi

read -r -p "Type APPROVE to sign + broadcast over Tor: " ans
[ "$ans" = "APPROVE" ] || { echo "cast-approve: aborted (nothing broadcast)."; exit 0; }

# Build the send: high-level sig+args (cast re-encodes → matches the decode the
# operator just reviewed) or a plain value transfer.
send=( "$TO" )
[ -n "$SIG" ] && send+=( "$SIG" "${ARGS[@]}" )
[ "$VALUE" != "0" ] && send+=( --value "$VALUE" )
send+=( --chain "$CHAIN" --rpc-url "$RPC" )

case "$CUSTODY" in
  keystore)
    if   [ -n "$ACCOUNT" ];  then send+=( --account "$ACCOUNT" )
    elif [ -n "$KEYSTORE" ]; then send+=( --keystore "$KEYSTORE" )
    else echo "cast-approve: --custody keystore needs --account NAME or --keystore PATH" >&2; exit 2; fi
    echo "cast-approve: enter the keystore password at the prompt (it is read here, never by ops)."
    ;;
  trezor)
    send+=( --trezor )
    echo "cast-approve: confirm the transaction on the Trezor at the box console." ;;
  airgap)
    echo "cast-approve: --custody airgap is a reserved future seam (laptop-side" >&2
    echo "  Trezor signing); not implemented. Use keystore or trezor." >&2
    exit 2 ;;
  *)
    echo "cast-approve: unknown custody '$CUSTODY'" >&2; exit 2 ;;
esac

set +e
sudo "$CAST_TOR" send "${send[@]}"
rc=$?
set -e
if [ "$rc" -eq 0 ]; then
  mv -- "$full" "${full%.casttx}.broadcast" 2>/dev/null || true
  echo "cast-approve: broadcast complete."
fi
exit "$rc"
#+end_src

** Stablecoin Convenience Wrappers (=stable-send= / =stable-bal=)

A *stablecoin wallet* is not a distinct object: USDC/USDT/DAI are ERC-20 tokens,
and the wallet that holds them is just an *EVM account* (one keypair → one
address, the *same address on every chain*). =cast= already covers the whole
lifecycle — *create* (=cast wallet import=, local, no network), *receive* (hand
out the address), *balance* (=balanceOf= read), *send* (=transfer= via the
propose/approve signer). These two wrappers add nothing to the trust surface;
they only close the two ergonomic gaps =cast= leaves for tokens:

1. A *token registry* — symbol → contract + decimals, per chain — so you write
   =usdc= and =base=, not a raw =0x…= address and a chain id.
2. *Decimal conversion* — USDC is *6* decimals, not 18. Sending the raw integer
   =50= instead of =50000000= is a catastrophic footgun; the wrapper converts a
   human amount using the registry's =decimals= and *fails closed* on excess
   precision.

The registry is rendered from =interop_chains= / =interop_tokens= (config.yml)
into plain space-separated *data* files under =interop_registry_dir= that the
wrappers =awk=-lookup — *data, not sourced code*. The contract addresses are
*config you audit*: confirm each against the issuer (Circle, for USDC) before
funding.

- =stable-send <symbol> <amount> <to> --chain <name>= is a *thin, OFFLINE*
  front-end to =cast-propose=: it resolves the token + decimals, converts the
  amount, and stages a =transfer(address,uint256)=. No network, no key — so it
  is *ops-runnable* exactly like =cast-propose=. You still finish with
  =cast-approve= (re-encode, re-simulate over Tor, sign). The auto-generated
  =--note= carries the approve-time RPC hint, because an *L2* proposal must be
  approved against that L2's RPC (=cast-approve <file> --rpc-url <l2-rpc>=) — the
  chain id travels in the proposal, but the RPC endpoint does not.
- =stable-bal <symbol> <address> --chain <name>= is an *operator-side read*: a
  =balanceOf= call over the fail-closed Tor netns (=sudo cast-tor= — the existing
  grant), formatted back to a human amount by the token's decimals.

(For the sandboxed =ops= front door to stage with =stable-send=, the bubblewrap
jail must expose =/usr/local/bin/stable-send= and =interop_registry_dir= — a
one-line follow-up in =org/14-sandbox.org=. The operator can use both directly
regardless.)

#!/bin/bash
# stable-send — stage a stablecoin (ERC-20) transfer for operator approval.
# Generated from org/30-interop.org.
#
# A thin, OFFLINE front-end to cast-propose: it looks up the token contract +
# decimals from the registry, converts a human amount to base units, and stages
# an ERC-20 transfer(address,uint256). It makes NO network connection and
# touches NO key — exactly like cast-propose, which it execs. Approve it with
# cast-approve (as the key owner, NOT ops).
set -euo pipefail

PROPOSE="/usr/local/bin/cast-propose"
REG="{{ interop_registry_dir }}"
TOKENS="$REG/tokens"
CHAINS="$REG/chains"

usage() {
  cat >&2 <<'USAGE'
Usage: stable-send <symbol> <amount> <to-address> --chain <name> [options]
  <symbol>        token symbol in the registry, e.g. usdc
  <amount>        human amount, e.g. 50 or 12.5 (converted using the token decimals)
  <to-address>    0x recipient (20-byte address)
  --chain NAME    chain name in the registry, e.g. base | arbitrum (required)
  --custody NAME  keystore | trezor | airgap  (passed through to cast-propose)
  --note 'text'   override the auto-generated approval note

Stages an ERC-20 transfer WITHOUT signing/broadcasting (offline), then prints the
proposal path. Approve it (as the key owner, NOT ops):
  cast-approve <path> --rpc-url <the chain's RPC>
USAGE
  exit 2
}

CHAIN="" CUSTODY="" NOTE=""
POS=()
while [ $# -gt 0 ]; do
  case "$1" in
    --chain)   CHAIN="${2:?}"; shift 2 ;;
    --custody) CUSTODY="${2:?}"; shift 2 ;;
    --note)    NOTE="${2:?}"; shift 2 ;;
    -h|--help) usage ;;
    -*)        echo "stable-send: unknown option: $1" >&2; usage ;;
    *)         POS+=("$1"); shift ;;
  esac
done
[ "${#POS[@]}" -eq 3 ] && [ -n "$CHAIN" ] || usage
SYMBOL="${POS[0]}"; AMOUNT="${POS[1]}"; TO="${POS[2]}"

[[ "$TO" =~ ^0x[0-9a-fA-F]{40}$ ]]        || { echo "stable-send: <to-address> must be a 0x 20-byte address" >&2; exit 2; }
[[ "$AMOUNT" =~ ^[0-9]+(\.[0-9]+)?$ ]]    || { echo "stable-send: <amount> must be a decimal number" >&2; exit 2; }
[ -r "$TOKENS" ] && [ -r "$CHAINS" ]      || { echo "stable-send: registry $REG missing (deploy --tags interop)" >&2; exit 1; }

# Resolve chain id + rpc (registry columns: name chainid rpc_url).
read -r CHAINID CRPC < <(awk -v n="$CHAIN" '$1==n {print $2, $3; exit}' "$CHAINS")
[ -n "${CHAINID:-}" ] || { echo "stable-send: chain '$CHAIN' not in $CHAINS" >&2; exit 2; }

# Resolve token address + decimals (registry columns: chain symbol address decimals).
read -r ADDR DEC < <(awk -v c="$CHAIN" -v s="$SYMBOL" '$1==c && $2==s {print $3, $4; exit}' "$TOKENS")
[ -n "${ADDR:-}" ] || { echo "stable-send: token '$SYMBOL' on chain '$CHAIN' not in $TOKENS" >&2; exit 2; }

# Human amount -> integer base units; fail closed if more fractional digits than
# the token has decimals (silently dropping them would send the wrong amount).
to_base_units() {
  local amt="$1" dec="$2" int frac out
  int="${amt%%.*}"
  if [[ "$amt" == *.* ]]; then frac="${amt#*.}"; else frac=""; fi
  [ "${#frac}" -le "$dec" ] || { echo "stable-send: $amt has more than $dec decimal places ($SYMBOL)" >&2; return 1; }
  while [ "${#frac}" -lt "$dec" ]; do frac="${frac}0"; done
  out="${int}${frac}"
  out="${out#"${out%%[!0]*}"}"   # strip leading zeros (avoid octal/empty)
  printf '%s' "${out:-0}"
}
UNITS="$(to_base_units "$AMOUNT" "$DEC")" || exit 2
[ "$UNITS" != "0" ] || { echo "stable-send: amount resolves to 0 base units" >&2; exit 2; }

# The note rides into the proposal; cast-approve shows it. Carry the RPC hint so
# the approver knows which (L2) endpoint to pass — the chain id is in the
# proposal, the RPC is not.
NOTE="${NOTE:-transfer $AMOUNT $SYMBOL on $CHAIN to $TO | approve: cast-approve <file> --rpc-url $CRPC}"

echo "stable-send: staging transfer of $AMOUNT $SYMBOL = $UNITS base units ($DEC dp)" >&2
echo "             token $ADDR  chain $CHAIN (id $CHAINID)  ->  $TO" >&2

exec "$PROPOSE" \
  --to "$ADDR" \
  --chain "$CHAINID" \
  --sig 'transfer(address,uint256)' \
  ${CUSTODY:+--custody "$CUSTODY"} \
  --note "$NOTE" \
  "$TO" "$UNITS"

#!/bin/bash
# stable-bal — show a stablecoin (ERC-20) balance over Tor, decimal-formatted.
# Generated from org/30-interop.org.
#
# Operator-side read: a balanceOf() call routed through the fail-closed Tor netns
# (sudo cast-tor — the existing grant), formatted with the token's decimals.
# Read-only; it signs and broadcasts nothing.
set -euo pipefail

CAST_TOR="/usr/local/bin/cast-tor"
REG="{{ interop_registry_dir }}"
TOKENS="$REG/tokens"
CHAINS="$REG/chains"

usage() {
  cat >&2 <<'USAGE'
Usage: stable-bal <symbol> <address> --chain <name> [--rpc-url URL]
  <symbol>      token symbol in the registry, e.g. usdc
  <address>     0x account to query
  --chain NAME  chain name in the registry, e.g. base | arbitrum (required)
  --rpc-url URL override the registry's RPC for this chain

Reads balanceOf() over Tor (sudo cast-tor) and prints it formatted by the token's
decimals.
USAGE
  exit 2
}

CHAIN="" RPC=""
POS=()
while [ $# -gt 0 ]; do
  case "$1" in
    --chain)   CHAIN="${2:?}"; shift 2 ;;
    --rpc-url) RPC="${2:?}"; shift 2 ;;
    -h|--help) usage ;;
    -*)        echo "stable-bal: unknown option: $1" >&2; usage ;;
    *)         POS+=("$1"); shift ;;
  esac
done
[ "${#POS[@]}" -eq 2 ] && [ -n "$CHAIN" ] || usage
SYMBOL="${POS[0]}"; ADDRQ="${POS[1]}"
[[ "$ADDRQ" =~ ^0x[0-9a-fA-F]{40}$ ]] || { echo "stable-bal: <address> must be a 0x 20-byte address" >&2; exit 2; }
[ -r "$TOKENS" ] && [ -r "$CHAINS" ]  || { echo "stable-bal: registry $REG missing (deploy --tags interop)" >&2; exit 1; }

read -r CHAINID CRPC < <(awk -v n="$CHAIN" '$1==n {print $2, $3; exit}' "$CHAINS")
[ -n "${CHAINID:-}" ] || { echo "stable-bal: chain '$CHAIN' not in $CHAINS" >&2; exit 2; }
RPC="${RPC:-$CRPC}"
[ -n "$RPC" ] || { echo "stable-bal: no RPC for '$CHAIN' (set interop_chains or pass --rpc-url)" >&2; exit 2; }

read -r ADDR DEC < <(awk -v c="$CHAIN" -v s="$SYMBOL" '$1==c && $2==s {print $3, $4; exit}' "$TOKENS")
[ -n "${ADDR:-}" ] || { echo "stable-bal: token '$SYMBOL' on chain '$CHAIN' not in $TOKENS" >&2; exit 2; }

raw="$(sudo "$CAST_TOR" call "$ADDR" 'balanceOf(address)(uint256)' "$ADDRQ" --chain "$CHAINID" --rpc-url "$RPC")"
raw="${raw%% *}"

from_base_units() {
  local r="$1" dec="$2"
  [ "$dec" -eq 0 ] && { printf '%s' "$r"; return; }
  while [ "${#r}" -le "$dec" ]; do r="0$r"; done   # left-pad so an int part exists
  printf '%s.%s' "${r:0:${#r}-dec}" "${r:${#r}-dec}"
}
printf '%s %s (chain %s)\n' "$(from_base_units "$raw" "$DEC")" "${SYMBOL^^}" "$CHAIN"

** Rabby Extension — Dapp-UI Fallback (opt-in, off by default)

=cast= is the primary workhorse, but a few interactions genuinely need a dapp's
*web frontend* (a site that only speaks to an injected wallet). For those, this
adds the *Rabby* browser extension — *not* a second standalone app. It is gated
on its own =rabby_enabled= flag, *independent of =cast_enabled=*: you can run
=cast= without ever installing a browser wallet.

It deliberately *reuses the existing fail-closed Mullvad browser path* (privacy
phase) rather than building new browser/VPN plumbing. Clearnet dapp frontends
are Tor-hostile (Cloudflare blocks Tor exits, latency breaks dapps), so this
edge rides *Mullvad*, while =cast= rides *Tor* — the project's existing layered
model. Rabby runs in a *dedicated =wallet= Chromium profile*, compartmentalized
from general browsing so the hot wallet is never mixed with anything else.

*** Why a self-packed, force-installed crx (and not the Web Store)

Rabby publishes its extension as a *single GitHub release zip* with *no checksum
and no signature* — weaker provenance than Foundry (which at least ships a
Sigstore bundle). This is inherent to the browser-extension model: the signature
in the normal install path is *Google's*, applied when the Web Store packs the
=.crx=, not the developer's — the GitHub zip is just the raw pre-store build. So
the strongest anchor available is a *SHA-256 we pin* (=rabby_sha256=); the
download is verified against it and *fails closed* on mismatch. Recorded in
=keys/README.md= as the second non-GPG anchor.

For *install*, pulling from the Chrome Web Store (=ExtensionInstallForcelist=
with Google's update URL) was rejected: it is a Google round-trip that serves
*whatever the store currently has* — you cannot pin or audit the bytes, against
this repo's verify-everything ethos. Loading the raw unzipped directory was also
rejected: since Chromium 133 *unpacked* extensions are auto-disabled unless
developer mode is on, and =--load-extension= is being removed. So we *pack the
verified bytes into a signed =.crx=* with a *locally-generated* key (a packed
extension is exempt from the developer-mode rule), then *force-install it from a
local =file://= update manifest*. No Web Store, no remote update server, no
Google in the loop — the bytes Chromium loads are exactly the ones we verified.
The packing key's only job is to satisfy Chromium's packed-extension
requirement and give the extension a *stable ID*; trust comes from the pinned
SHA-256 of the source zip, not from this self-signed key.

*** What the pin guarantees (and what it does not)

Be clear about what =rabby_sha256= buys, because it is easy to overstate. The pin
is a *consistency check, not a code audit*. It guarantees you receive the *exact
bytes that were pinned* — so it *fails closed* against a *targeted* swap (a
man-in-the-middle, a poisoned mirror, bad DNS serving you a different file). The
recommended way to set it is to cross-check the published hash over *more than
one path* (clearnet and Tor) before pinning, the same discipline =keys/README.md=
prescribes for the GPG keys.

It does *nothing* against *upstream compromise*: if RabbyHub's account is popped
and a malicious release ships to everyone, or Rabby is simply hostile, every path
agrees on the same poisoned hash and the pin passes happily. Confirming the bytes
are authentic is not the same as confirming they are safe — and actually auditing
a minified, bundled MV3 extension (or its whole npm dependency tree, if built
from source) is not realistically achievable here. So the pin is the *integrity*
control; the *safety* backstop is custody, below.

*** Custody and WebRTC

A wallet living in a browser profile is a *hot key*, and — per the section above —
the extension's provenance is the weakest anchor in this repo and cannot be
audited away. So for this path a *hardware wallet is the expected posture, not a
nicety* (Rabby supports Trezor/Ledger; the Trezor udev rules are already
installed for =cast=). With it, Rabby never holds the key: it builds the
transaction, but you confirm the *real destination and amount on the Trezor's own
screen*, outside the extension's reach. That is the one control that survives an
upstream compromise you cannot audit — a backdoored Rabby can show you a lie in
the browser, but cannot silently move a hardware-backed account's funds. Treat a
plain hot key in the profile (no hardware wallet) as a *last resort* for trivial
amounts only.

The managed policy also sets WebRTC to =disable_non_proxied_udp= as
belt-and-braces against an IP leak, even though Mullvad is already the only exit.

** Notes

*** Three layers of "off"

1. =cast_enabled: false= → nothing lands (no binary, no cosign/nftables, no
   namespace config).
2. Installed-but-no-service → nothing runs at boot.
3. On-demand =cast-tor= → the dedicated Tor and the network namespace exist only
   for the duration of one =cast= invocation, then are torn down.

*** Running cast

#+begin_example
# Always via the launcher (never bare `cast` — that would not be torified):
cast-tor block-number --rpc-url https://1rpc.io/eth
cast-tor balance 0xYourAddress --rpc-url https://1rpc.io/eth
cast-tor call <contract> "name()(string)" --rpc-url https://1rpc.io/eth

# Sending (hardware wallet; confirm on the Trezor at the console):
cast-tor send <contract> "transfer(address,uint256)" <to> <amount> \
  --trezor --rpc-url https://1rpc.io/eth
#+end_example

The first run with a fresh Tor data dir takes ~10–30 s to bootstrap; later runs
are faster because the guard nodes persist in ={{ interop_tor_data_dir }}=.

*** No-log RPC endpoints

=cast= needs a JSON-RPC endpoint. Choose a *no-log* provider and pass it
explicitly with =--rpc-url= — never rely on a hidden default. Reasonable choices
(set =cast_rpc_url= in =config.yml= if you want a documented default, or just
pass =--rpc-url= each time):

- =https://1rpc.io/…= (TEE-attested, zero-trace)
- PublicNode (=https://…-rpc.publicnode.com=)
- LlamaRPC (=https://…/rpc.llamarpc.com=)

No chain or asset is baked in — this is general infrastructure; you pick the
endpoint per call.

*** Confirming there is no leak (on-box acceptance test)

The launcher already refuses to run unless =check.torproject.org/api/ip= reports
a Tor exit. To prove independently that *nothing* bypasses Tor, sniff the real
uplink while a =cast-tor= command runs:

#+begin_example
# Terminal A (host, real interface — expect ONLY encrypted Tor guard traffic,
# no plaintext DNS, no direct connection to the RPC host):
sudo tcpdump -ni <wan-iface> 'port 53 or host <rpc-ip>'

# Terminal B:
cast-tor block-number --rpc-url https://1rpc.io/eth
#+end_example

A DNS packet or a direct connection to the RPC host on the real interface would
indicate a leak; none should appear.

*** Custody and keys

- *Hardware wallet (preferred):* =cast … --trezor= (or =--ledger=). The key never
  touches disk; each signature needs a console button press. Trezor udev rules
  are installed by this phase. Back up the *seed* out-of-band (paper/steel) — it
  is never on the box.
- *Encrypted keystore (no-HW fallback):* =cast wallet import <name> --interactive=
  writes an encrypted JSON keystore under =~/.foundry/keystores=; use it with
  =--account <name> --password-file=… =. Still no plaintext key on disk. (Backing
  this directory up is handled when the backup hook for it is added.)

*** Why this is the "least-leaky" edge, not a maximally-private one

Interacting with a transparent public EVM chain is inherently less private than
Monero: balances, transfers, and contract calls are visible on-chain, and the
address graph is analyzable. This phase makes the *network* path sovereign and
private (self-hosted, Tor-routed, no trusted RPC that logs your IP) and keeps
*custody* hardware-backed — but it does not, and cannot, make the *chain*
private. It exists because some interop is necessary, and this is the least-leaky
way to do it.

*** The Rabby fallback is the least-private edge — use it rarely

Everything that makes the chain transparent applies, *plus* a browser attack
surface and Rabby's DeBank phone-home. This path neutralizes the IP exposure
(Mullvad-only egress, WebRTC off) and compartmentalizes it (dedicated =wallet=
profile, hardware-wallet custody), but it cannot make a browser-driven dapp as
private as =cast=. Reach for =cast= first; use =rabby-wallet= only when a dapp
genuinely has no non-browser path. Honest limits: some sites still challenge or
block VPN exit IPs, so a given dapp may simply not load.

To prove the Mullvad path doesn't leak, the same kind of on-box check as cast's
applies — sniff the real uplink while =rabby-wallet= runs and confirm traffic
only goes to the Mullvad endpoint (no direct connection to the dapp/RPC host).

*** Updating

A presence-based =update-cast= (bump =foundry_version= in =config.yml=, re-verify
via cosign, atomic =/opt/foundry= symlink switch) is added with the other
updaters. There is no service to restart.

=update-rabby= follows the same shape: bump =rabby_version= *and* =rabby_sha256=
in =config.yml= (the new hash audited out-of-band), re-run =--tags interop=. The
download re-verifies against the new pin, re-packs the =.crx= with the existing
key (so the extension ID is unchanged), and refreshes the local update manifest;
Chromium reloads the force-installed extension. No service to restart.
